## 0. MVPスコープ（優先度定義）

> **レビュー指摘対応:** 8/31までの実装範囲を明確化するため、各機能に優先度を付与。

| 優先度 | 意味 | 対象機能 |
|--------|------|----------|
| **P0** | MVP必須。これがないとプロダクトとして成立しない | ログイン/登録、ホーム画面、投稿作成・詳細、基本的なタイムライン、ストリーク（投稿継続カウンター） |
| **P1** | MVPに含めたい。P0完了後に着手 | 感情グラフ（インタラクティブジャンプ付き）、通知画面（「○年前の今日」）、AI検索UI |
| **P2** | 後回し可。MVP後に追加 | ルーム機能、AI要約、エクスポート機能、オフライン対応、ダークモード |

### 削減方針

- P0のみで8/31デモを成立させる
- P1はP0が安定したら着手し、デモ当日に「もう少しあるよ」と見せられる程度
- P2は設計のみ先に行い、実装はMVP後

### 認証フロー（OAuth → JWT）

> **レビュー指摘対応:** ログイン画面にOAuthボタンがあるのに認証方式がJWTのみだったため、フローを補記。

```text
[ユーザー] → Google/SNSボタンクリック
    ↓
[ブラウザ] → OAuthプロバイダーへリダイレクト
    ↓
[OAuthプロバイダー] → 認証完了、コールバックURLへリダイレクト
    ↓
[バックエンド] → /auth/callback でアクセストークン取得
    ↓
[バックエンド] → ユーザー情報をDBに保存/更新、JWTトークン発行
    ↓
[ブラウザ] → JWTトークンをlocalStorageに保存しホームへ遷移
```

# 8. 認証・権限

## 認証フロー

> **レビュー指摘対応:** OAuth → JWTトークン発行のフローを明記。

### フロントエンド側の認証フロー

```text
1. ユーザーがGoogle/SNSボタンをクリック
2. /auth/google または /auth/sns へリダイレクト
3. OAuthプロバイダーで認証
4. コールバックURL（/auth/callback）に戻る
5. バックエンドがJWTトークンを発行
6. フロントエンドがJWTトークンをlocalStorageに保存
7. 以降のAPIリクエストにAuthorization: Bearer <JWT>を付与
```

### JWTトークン管理

| 項目 | 仕様 |
|------|------|
| 保存場所 | localStorage |
| 有効期限 | アクセストークン: 1時間、リフレッシュトークン: 7日 |
| リフレッシュ | アクセストークン期限切れ時にリフレッシュトークンで更新 |
| ログアウト | localStorageからトークン削除 |

# 9. AI検索UI仕様（P1）

> **レビュー指摘対応:** 「入力→AIローディング→結果表示」の状態遷移とUI仕様を追加。

## 検索画面の状態遷移

```text
[初期状態] 検索入力欄 + 最近の検索履歴
    ↓
[ユーザーがクエリ入力 → 検索ボタンクリック]
    ↓
[ローディング状態] 「AIがあなたの思い出を探しています...」
  - スピナー表示
  - 推定検索時間の表示（例: 「約3秒で結果が出ます」）
  - キャンセルボタン
    ↓
[結果表示] 検索結果カード一覧
  - 関連度スコア付き
  - 投稿サムネイル
  - 抜粋テキスト
    ↓
[エラー時] 「検索に失敗しました。もう一度お試しください。」
  - 再試行ボタン
```

## 検索結果の表示仕様

| 項目 | 仕様 |
|------|------|
| 結果カード | 写真サムネイル + 抜粋テキスト + 感情アイコン + 日付 |
| 関連度 | パーセンテージまたは星マークで表示 |
| ソート | 関連度順（デフォルト）、日付順（切替可） |
| ページネーション | 20件ずつ、無限スクロール |

## AI検索のタイムアウト

| 状況 | 対応 |
|------|------|
| 3秒以内 | 通常表示 |
| 3-10秒 | 「もう少しお待ちください...」 |
| 10秒超 | タイムアウトエラー + 再試行ボタン |

# 13. データ継続性・エクスポート仕様

> **レビュー指摘対応:** 70〜80年後の媒体移行を想定したデータフォーマットを定義。
> **注:** JSONスキーマの最終定義はバックエンド班との合意が必要。

## 設計方針

* 投稿データはJSON形式でエクスポート可能
* 将来的な媒体移行（Web → AR等）を考慮したフォーマット
* メタデータとメディアファイルを分離

## 投稿データJSONスキーマ（暫定）

```json
{
  "version": "1.0",
  "exported_at": "2026-08-31T00:00:00Z",
  "user": {
    "id": "user_123",
    "name": "太郎",
    "created_at": "2026-08-01T00:00:00Z"
  },
  "posts": [
    {
      "id": "post_456",
      "created_at": "2026-08-15T12:00:00Z",
      "text": "今日は友達とお花見をした！",
      "emotion": "happy",
      "emotion_score": 0.95,
      "tags": ["お花見", "友達", "春"],
      "media": [
        {
          "type": "image",
          "url": "https://r2.example.com/media/img_001.jpg",
          "filename": "hanami_001.jpg"
        },
        {
          "type": "audio",
          "url": "https://r2.example.com/media/voice_001.mp3",
          "filename": "voice_memo_001.mp3",
          "duration_seconds": 30
        }
      ],
      "location": {
        "name": "上野公園",
        "lat": 35.7148,
        "lng": 139.7710
      }
    }
  ]
}
```

## メディアファイルの扱い

| 項目 | 仕様 |
|------|------|
| 保存先 | Cloudflare R2 |
| URL形式 | 絶対URL（媒体移行後もアクセス可能） |
| エクスポート | JSON + メディアファイル一括ダウンロード（ZIP） |
